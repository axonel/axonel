# Sentinel CLI Reference

The `sentinel` command-line interface provides operational management of the Sentinel supervisor daemon, project workspaces, and autonomous engineering missions.

```text
Usage: sentinel [COMMAND]

Commands:
  serve      Start the Sentinel operational control plane server
  init       Initialize a project workspace for Sentinel
  status     Inspect system and workspace operational status
  mission    Manage autonomous engineering missions
  reconcile  Run deep startup and recovery reconciliation
  help       Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version
```

---

## 1. `sentinel serve`

Starts the Sentinel operational control plane server and static Web Operations Dashboard.

```bash
sentinel serve [OPTIONS]
```

### Options
- `--host <HOST>`: Bind address. Defaults to `127.0.0.1` (loopback).
- `-p, --port <PORT>`: Listen port. Defaults to `3000`.
- `--db <DB>`: Path to the SQLite database file or `:memory:`. Defaults to `plexis.db`.
- `--auth-token <AUTH_TOKEN>`: Optional authentication bearer token. **Mandatory** when binding to non-loopback addresses (`0.0.0.0` or public interfaces).

### Examples
```bash
# Start standard local daemon on 127.0.0.1:3000
sentinel serve

# Start on a custom port with bearer token authentication
sentinel serve --port 8080 --auth-token "my-secret-token"
```

## 2. `sentinel init`

Initializes a project workspace for Sentinel in the target directory, detecting project characteristics.

```bash
sentinel init [OPTIONS] [PATH]
```

### Arguments & Options
- `[PATH]`: Target directory to initialize as a workspace. Defaults to the current working directory.
- `-n, --name <NAME>`: Friendly name for the workspace.
- `--db <DB>`: Path to the SQLite database. Defaults to `plexis.db`.

### Example
```bash
sentinel init . --name "payments-service"
```

## 3. `sentinel status`

Inspects authoritative storage and prints system, daemon, and workspace operational status.

```bash
sentinel status [--db <DB>]
```

## 4. `sentinel mission`

Commands to create, inspect, review, accept, reject, and integrate autonomous missions.

```text
Usage: sentinel mission [OPTIONS] <COMMAND>

Commands:
  create     Create and dispatch a new autonomous mission
  status     Inspect mission status, cycle progress, and checkpoints
  diff       Show the Git diff generated by the mission
  review     Inspect the comprehensive review package before acceptance
  accept     Explicitly accept a verified mission result
  reject     Non-destructively reject a mission result with audit reason
  integrate  Safely integrate an accepted mission into target branch
```

### `sentinel mission create`
Creates and dispatches a new autonomous mission.

```bash
sentinel mission create [OPTIONS] --objective <OBJECTIVE> <PATH>
```
- `<PATH>`: Target workspace path or repository directory.
- `-o, --objective <OBJECTIVE>`: Mission objective prompt.
- `-t, --title <TITLE>`: Optional mission title.
- `--auto-start`: Automatically start the mission upon creation (default: `true`).

### `sentinel mission status <ID>`
Inspects cycle progress, current state, active checkpoints, and resource consumption.

### `sentinel mission diff <ID>`
Displays the unified Git diff generated by the candidate deliverable in its isolated worktree.

### `sentinel mission review <ID>`
Renders the complete review package: changed files list, verification receipts, target branch freshness, and diff summary.

### `sentinel mission accept <ID>`
Explicitly accepts a verified deliverable.
- `--integrate`: Atomically integrates into the target branch upon acceptance.
- `--branch <BRANCH>`: Target git branch (defaults to `main`).
- `--message <MESSAGE>`: Optional custom merge commit message.

### `sentinel mission reject <ID>`
Non-destructively rejects a candidate deliverable, recording an auditable reason in the event stream.
- `-r, --reason <REASON>`: Required explanation for rejection.
- `--replan`: Requests another autonomous cycle with corrective feedback.

### `sentinel mission integrate <ID>`
Integrates an already-accepted mission into the target branch.
- `--branch <BRANCH>`: Target git branch (defaults to `main`).
- `--message <MESSAGE>`: Optional custom commit message.

## 5. `sentinel reconcile`

Manually triggers deep startup and crash recovery reconciliation. Inspects the SQLite event store and physical Git repositories to reconcile intermediate states, reclaim expired leases, and unstick orphaned tasks.

```bash
sentinel reconcile [--db <DB>]
```
